# Shared Graph canvas and host interface laboratory

<a id="host-and-delivery-constraints"></a>

The current prototype displays a caller-selected Graph Skill and lets a user test the connected host's generic operations. One [HTML template](ui/template/canvas.html) serves Codex as an MCP App and Claude as an authenticated HTTP preview. An MCP App is an interactive page attached to a Model Context Protocol tool result. The [Graph application](application/graph/service/index.mjs) reads an explicit business root, projects its graph and identifies its `SKILL.md`; the independent Python runtime owns complete format validation and execution. A missing root displays a labeled demonstration.

The [canvas](ui/canvas/view.tsx) draws nodes and edges and supports pointer and keyboard node selection. The [workbench](ui/workbench/index.tsx) arranges the graph and selected-node details. When the runtime rejects the selected Skill, the workbench shows the [invalid-graph notice](ui/diagnostics/index.tsx), a prominent alert above the graph area. Its heading states the number of problems the runtime reported. Its list gives each runtime compile diagnostic verbatim: code, message, `source_path:line` and field path, with at most 50 entries and a count of the entries left out. A note states that the graph below is the last compiled version, or that no compiled version exists yet. The last compiled graph stays visible, dimmed, beneath the notice. The next snapshot from a valid save clears the notice and draws the new graph in the same page. [Host status](ui/host_status/index.tsx) displays the connected `HostInfo` identity/version and the toolkit plugin version from `package.json` separately. Unknown host facts remain unknown. The [interface laboratory](ui/interface_lab/index.tsx) lists the 15 operations from the [catalog](ports/host/catalog.mjs), shows each current `available`/`unavailable`/`unknown` capability with its reason, and offers editable JSON arguments. Graph-specific [sample values](application/graph/interface_samples/index.mjs) may prefill a selected root, document, context or inspection tool; callers can replace them. Selecting a node alone does not submit a message or mutate the business Skill.

An operation is enabled only when the page is connected and the current host declares that operation available. The [contract](ADAPTER.md#interface-contract) owns names, parameters, status meanings and host limits. The laboratory records the result and response data. `accepted` proves only a host request was received; observe an actual file view, draft, conversation or tool result separately. `pending` preserves an uncertain request; Claude's receipt lookup queries that same request ID without replay. A Codex uncertain result needs host observation because its page connection has no receipt query. Input validation or host refusal appears as an error or rejection rather than apparent completion.

Generic host operations and Graph presentation have different purposes. The canvas server exposes Graph-specific `show_graph` and read-only `inspect_graph`; a sample `tools.call` may name `inspect_graph`, but the Port is not limited to that tool. Codex's normal Skill presentation calls `show_graph` once; the attached MCP App view is the canvas. Its presentation resource/session modules own widget metadata and reuse. Claude's Mod obtains the actual preview project and session, uses `preview_start`/name, navigation and tab selection to the owned HTTP page, and retains the canvas view. Its presentation guidance is separate from generic `views.open`, whose availability remains unknown. The [Graph Skill instruction asset](skills/graph-skill/SKILL.md) continues to guide normal host use.

The prototype is an interface test surface and graph viewer. Source and fake-host checks can verify rendering, arguments and bounded adapter calls; they cannot show that all 15 effects work in an installed native host. [VALIDATION.md](VALIDATION.md) states current check scope, and [MANUAL-TESTS.md](MANUAL-TESTS.md) gives the native observation procedure. The prior eight-control observations are historical results for earlier candidate bytes.
