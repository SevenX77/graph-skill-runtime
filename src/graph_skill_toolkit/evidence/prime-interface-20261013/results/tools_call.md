- **Codex: conditional source-level connection.** `host_interfaces/tools/call/codex.mjs` requires advertised `serverTools` and rejects session scope or a server other than the confirmed originating server. The installed `@modelcontextprotocol/ext-apps` declaration `node_modules/@modelcontextprotocol/ext-apps/dist/src/app.d.ts:638-673` specifies `App.callServerTool` proxied by the host to the originating MCP server, with direct tool results and `isError`. Existing code returns that result via `responseResult`; the focused test checks exact `{name, arguments}`, foreign scope rejection and `isError`. A live Codex Desktop call on candidate bytes is unverified.
- **Claude: conditional source-level connection.** `evidence/reverse-resume-20261011/anthropic-mod-types.d.ts.txt:2559-2581, 4976-5028, 9822-9890, 10079-10095` describes current-session `$.tool.list()` with MCP flag, flattened `$.tool.call({tool,...args})` including MCP names, permission checks/dialog, denial and error result. The former explicit-server path called `$.mcp.call` while the same declaration `:2319-2340` says **no permission prompt**. This contradicted `ADAPTER.md`'s host-permission promise. I replaced only this owned module's explicit-server path with the listed full `mcp__<server>__<name>` identity through `callNative`/`$.tool.call`; no `$.mcp.call` or prompt submission is performed. Calls with an unlisted target, mismatched scope or reserved envelope input are rejected before dispatch. In particular `consent` and `agentId` are reserved host metadata per declaration `:9771-9820`, and `tool`/`tool_use_id` are rejected by existing `callNative`. Empty inventory now advertises unavailable. Claude can deny a call; successful return is a direct tool result, not proof of later business outcome.
- **Alternative review:** retain `$.mcp.call` (high operational simplicity but explicitly bypasses permission; rejected, candidate confidence **0.20** for this contract). Use `$.tool.call` by exact listed name (candidate confidence **0.91** for documented shape and permission semantics; no Desktop test). Unknown server-name normalization may make an explicit `server` request unsupported even when the full `mcp__` name is listed; the caller can use the complete listed name without `server`, preserving permission and identity. Do not guess a normalized name or fall back to unprompted `$.mcp.call`. Validating a loaded host with an authorized harmless tool call, separately recording permission and returned result, would strengthen the selected route; a loaded host that does not expose it would overturn the operational claim.
