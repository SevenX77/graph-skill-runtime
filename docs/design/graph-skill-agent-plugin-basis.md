## Managed-runtime delivery decision, 2026-10-09

The adopted `0.2.0` delivery supplies the interpreters and base dependencies inside each platform archive. The user can extract a matching archive and run its installer. Runtime operations use shared Skills and the installed command-line interface (CLI). A Skill guides the host agent, and the CLI invokes runtime operations through its shell tools. The canvas uses a minimal MCP App: an HTML view linked to a tool result through the Model Context Protocol. This delivery preserves one product module, independent Python-package deployment, host-owned business files and manual acceptance in Codex Desktop and Claude Code Desktop.

It transcribes the user's question about compatibility of “Node.js 22+、Python 3.11+” prerequisites and the approval “好的，按这个方案实施” (“implement that approach”) after the coordinator recommended product-owned Python and an installer that requires neither preinstalled runtime. Original conversation access belongs to the coordinator; this writer verifies the supplied transcription, repository inputs and implementation. The [current validation baseline](../../plugins/graph-skill/VALIDATION.md#current-baseline-local-toolkit-delivery-2026-10-09) owns scope, four goal judgments, necessary results and evidence-bound acceptance.

The prerequisite concern has two distinct causes. A system-runtime prerequisite asks the user to install and select compatible interpreters. Runtime dependencies resolved during installation add index access and changing resolution to that first-use path. A complete archive removes those two steps by doing the resolution and assembly during the build. It still depends on the target operating system and native libraries. This reasoning supports a bounded private-runtime delivery claim; native compatibility and host rendering require their own observations.
