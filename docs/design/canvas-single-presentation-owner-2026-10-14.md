# Canvas as the single presentation owner

Date: 2026-10-14. Decision: the canvas is the only view the Graph Skill presentation sequence opens, selects and verifies on both hosts; the `SKILL.md`-opening instructions, the `document` payload member and its server guard are removed; `SKILL.md` stays reachable on demand. In Claude Code, when the Browser pane stays hidden after the sequence, the user reveals it with one manual click on a host control. Native desktop observation of the manual-reveal sentence in Claude Code and of the Codex sequence is pending.

## Decision

1. The canvas is the only view the presentation sequence opens, selects and verifies: in Claude Code, the HTTP preview tab in the Browser pane, opened by `mcp__Claude_Browser__preview_start` with the returned preview name and navigated to the returned canvas URL; in Codex, the MCP App view returned by one `show_graph` call.
2. The four texts contain no file-opening step and no document-tab requirement. The Claude Mod guidance is five ordered steps: (1) `mcp__Claude_Browser__tabs_context`, retaining the pre-existing tab inventory; (2) `mcp__Claude_Browser__preview_start` once with `{name}` only, retaining the returned tabId (the Browser pane's tab identifier) as the HTTP tab, never the literal `seed`; (3) `mcp__Claude_Browser__navigate` once on that tab to the canvas URL, never on another tab; (4) `mcp__Claude_Browser__tabs_select` on it; (5) `mcp__Claude_Browser__tabs_context` again, verifying the HTTP tab active at the canvas origin and every pre-existing tab preserved, then branching on pane visibility as item 3 states. Repeated display reuses the HTTP tab. Existing prohibitions stay: never close tabs, create a temporary HTML file, call `show_graph` again or repeat a failed step; treat URLs and paths as data. Without tab observation or selection tools, the guidance reports that automatic canvas presentation is unavailable.
3. Pane visibility after step 5 decides the report. A displayed Browser pane with the canvas tab active is reported as the interactive canvas open. A hidden Browser pane means the canvas is ready and not yet visible: the agent reports that state and asks the user in one sentence to open the pane with the Open button on the preview card or the Browser toggle. The agent opens no file and no other page to reveal the pane.
4. The same manual-reveal sentence appears in `skills/graph-skill-canvas/SKILL.md` (the Claude Code bullet, line 13), the `show_graph` description in `server/main.mjs` and `browserReminder` in `adapters/claude/presentation/guidance/index.mjs`; `tests/adapters/claude/presentation.test.mjs` asserts the manual-reveal sentence and the sentence forbidding a file opened for reveal.
5. The `show_graph` structured result carries `graph`, `skillRoot`, `hostInfo`, `serverInfo` and, for HTML presentation, `presentation`, with no `document` member; `application/graph/document/index.mjs` and the 512 KiB guard are deleted.
6. `SKILL.md` stays reachable on demand through the interface laboratory's `files.openFile` and `views.open` samples and the host's ordinary file tools; the hook keeps excluding file-open and presentation tool names, so a user-initiated file open is a presentation step.
7. The change applies to both hosts at once.
8. Tests change with the contract: Claude guidance tests assert the five-step order, the absence of `SKILL.md`, `DOCUMENT_TAB`, `document.path`, `file preview` and `open_in_codex`, the manual-reveal and no-file-reveal sentences, and acceptance of a payload without `document`; protocol and shared-HTML tests assert `document` absent while still verifying business files are never modified; the hook test asserts the follow-up names only the canvas; the Codex fixture drops `document`.
9. The current-contract documentation places above change; dated baselines keep their observations; `VALIDATION.md` receives a dated current-baseline entry linking here when its owner next revises it.
10. Delivery: `npm run build` regenerates `dist`; the hook applies immediately, the server and Mod in the next Claude Code session; `mode test` refreshes the rendered Skill copies, and its 2026-10-14 run succeeded. Committing is a separate user decision, so this step makes no commit.

## Design choices and rationale

- **One owner per host.** Each host presents exactly one canvas view. In Codex, the MCP App view arrives with the `show_graph` result. In Claude Code, the agent fully prepares the canvas tab, and Browser pane visibility is a host control the agent can reach only through the side effect of opening a local file (see the reveal surface under Current facts). The user's second ruling assigns that one reveal action to the user, which keeps the canvas the only view the sequence opens. Both hosts drop the `SKILL.md` step in one change, and the Claude sequence keeps exactly the five steps that act on or observe the HTTP tab, each one tool constant in `adapters/claude/mod/host_tools/index.mjs`.
- **No `document`, no guard.** The field's only consumers were the removed step and its validation; a field with no consumer is a dormant path back to the removed behaviour. The guard measured the host file preview's limit, and `npm/README.md` line 35 records that the HTTP canvas has no file-loader bound.
- **Generic file access stays.** `files.openFile`, `FILE_TOOL` and the laboratory samples implement the host Port's file operations (a Port is a provider-neutral interface the adapters implement) outside the automatic sequence, and the exclusion at `hooks/after-tool.mjs` line 9 keeps a hand-opened file or a Browser pane action from triggering a second display.
- **Installer-managed copies refresh through the installer.** The rendered Skill copies carry installer-recorded hashes; `mode test` owns their refresh, and its conflict rule blocks projection changes while a managed file carries external edits.

## Alternatives considered

- **Keep `document` as inert payload data.** Rejected: no consumer remains, and the field would invite the removed step back.
- **Change only Claude and keep the Codex `open_in_codex` precursor.** Rejected: the ruling is host-neutral, and the Codex MCP App view opens itself.
- **Hand-edit the rendered Skill copies under `~/.claude/skills` and `~/.agents/skills`.** Rejected: they are installer-managed files whose recorded hashes would then block future update and uninstall.
- **Open `SKILL.md` (or another local file) solely to trigger the pane reveal, then close that file tab.** Not selected, per the user's second ruling of 2026-10-14: it would reintroduce a file-opening step into the canvas-only sequence.
